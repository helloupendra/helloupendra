## Featured work

### 🎙️ Ira — a self-hosted voice assistant you can trust with your own data

[source](https://github.com/helloupendra/ira) · [docs](https://helloupendra.github.io/ira/)
&nbsp;·&nbsp; `Python` `FastAPI` `Swift` `Kotlin` `AWS`

"Hey Ira": one assistant for a person or a business, running on their own server, over
their own tools and devices. You talk to it in Hindi, English or Hinglish, by text or by
voice, from the web, a Mac, an Android phone, an iPhone or Telegram.

- **Real-time voice** over one WebSocket protocol: speech-to-text streamed from Amazon
  Transcribe, the model's answer streamed sentence by sentence into Polly, and barge-in.
  The first answer audio arrives 1.7–2.2 s (median) after you stop speaking, as
  [measured](https://github.com/helloupendra/ira/blob/main/docs/realtime.md#measured)
  on the server.
- **Native clients** that pair as devices: a SwiftUI menu-bar app for the Mac (files, screen
  text read on the Mac, contacts, calendar, mail drafts, coding tasks in a sandboxed git
  worktree) and a Kotlin app for Android (calls, contacts, messages, notifications).
- **Safety in the design, not the prompt.** Every tool has a tier fixed in code: reads run,
  small actions are reported, outward actions are read back and need a "yes", and money,
  deletion or pushing code needs a PIN typed by the person. Anything a tool returns reaches
  the model marked as untrusted data, so a web page or an email cannot trigger an action.
- **Connections to anything** through MCP (with OAuth), with tiers taken from the tool's
  own annotations and only ever made stricter, plus a connector kit for any business API.
- **Learning that has to prove itself.** It notices routines only when switched on, and
  remembers one only after enough days of evidence *and* the person's yes; a sentence
  carrying a number it did not observe is refused.
- Any model provider with fallback chains and per-call cost; 680+ tests across the server
  and both apps.

### 🏦 OpenFNO — an algo-trading desk for Indian F&O

[**openfno.com**](https://openfno.com) · [source](https://github.com/helloupendra/algorithmic-trading-engine) · [docs](https://openfno.com/docs/)
&nbsp;·&nbsp; `C#` `Python` `React` `PostgreSQL` `Redis` `AWS`

A .NET 10 API, a React console and a Python strategy engine on one AWS box behind a
Cloudflare tunnel. It starts itself before the market opens, runs the session, squares off,
archives the day overnight, and deploys new commits on its own.

- Live ticks from Dhan with FYERS behind it, every tick stored, and an option chain that can
  be rebuilt for any past minute from recorded open interest.
- Backtests priced from six years of stored minute bars — including expired contracts the
  broker no longer serves — with slippage and a statutory charge table keyed by trade date.
- Risk rules at leg, group and run level, evaluated by the replay engine and by the live
  guard from the same definitions, so a backtest and a live run cannot quietly disagree.
- 27 strategy specifications: each states its rules, its parameters, and what it actually did.

### 🧾 OpenFNO Broker — a simulated Indian broker

[**broker.openfno.com**](https://broker.openfno.com) · [source](https://github.com/helloupendra/openfno-broker) · [the rules it enforces](https://github.com/helloupendra/openfno-broker/blob/main/docs/rules.md)
&nbsp;·&nbsp; `C#` `React` `PostgreSQL` `Docker`

Paper trading fills an order the moment a strategy decides to trade. A real broker first
checks the session, the caller's IP, the rate limit, the lot, the tick, the margin and the
market hours. This is that second world, without the money.

- The SEBI retail-algo framework in code — static-IP whitelisting, a daily TOTP login, ten
  order operations a second, no market orders — each rule citing the circular it comes from.
- Single-writer engine: decide → append to the journal → apply. The journal is the only
  durable state, and a restart replays it into exactly the state it left.
- Matching, charges by trading date, positions, contract notes, auto square-off, a kill
  switch, end-of-day settlement, and a sandbox that injects latency, exchange rejections,
  lost responses and outages.

## How I work

- **Write it down.** Every strategy, rule and deployment step in my own projects has a
  document beside the code, so a reviewer can check the code against a statement of what it
  is supposed to do.
- **Publish the evidence, including when it is unflattering.** My
  [study of Smart Money Concepts](https://github.com/helloupendra/algorithmic-trading-engine/blob/main/docs/smart-money-concepts.md)
  ends with a holdout test that took a promising three-year result to nothing — and that is
  in the document, because the next person to have the idea should find it there.
- **Test the awkward things.** Around 1,800 automated tests across those two projects. The
  ones I value most catch what an error message never would: replaying an event journal into
  a second engine to prove the two states match, or reading every prefix of a candle series
  to prove that no mark on a chart moves after it is drawn.
